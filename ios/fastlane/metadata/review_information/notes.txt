AI data sharing (Guidelines 5.1.1(i) and 5.1.2(i))
• KubePilot does not embed or call any AI service from the device. AI features send a request to the user's own KubePilot server, which runs the AI model it is configured with — by default a self-hosted model on that server (for example Ollama), or an OpenAI-compatible third-party service if the server operator configures one.
• Before any data is sent, the app shows a permission screen that lists exactly what is sent (the typed question plus a cluster-state summary; or the selected pod's name, namespace, status, events, resource usage and up to 200 recent log lines), names who receives it (the KubePilot server host, and the AI model and endpoint that server reports — flagged as a possible third-party provider when it is not on the server), and asks the user to Allow or Don't Allow. AI features are off until the user taps Allow.
• To see it: sign in to the demo, open a pod and tap "Analyse with AI", or send a message in the AI tab. The choice can be reviewed or withdrawn in Settings → AI & Privacy, which also links to the privacy policy (https://pages.kubepilot.org/privacy.html, section "AI features and AI services").
• On the demo server the AI responses are synthetic sample data and no third-party AI service is involved.

Notes
• The demo API returns synthetic cluster data only (for example CrashLoopBackOff and sample AI analysis). It does not expose customer clusters or real kubeconfigs.
• If the demo host is temporarily unreachable, Try demo falls back to the same sample data offline so you can still exercise the main screens.
• Reviewers with their own KubePilot backend may instead enter that server URL and credentials on Welcome.

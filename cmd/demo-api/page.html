What the simulation does

Always on: one checkout-api replica crash-loops after a bad config change, with kubelet back-off timing and restart counts that keep climbing.

Rotating every 30 minutes: an OOMKilled indexer, a rollout stuck on ImagePullBackOff, a node under disk pressure, or a worker node going NotReady.

Live: node CPU and memory drift over time, logs stream new lines, pods roll weekly, and resolved incidents stay in RCA history. Every replica of this API shows the same cluster at the same moment.

Your own cluster

Connect KubePilot to your Kubernetes clusters

The demo can't see your cluster, and your cluster's data never passes through demo.kubepilot.org. KubePilot runs next to your cluster, and the app connects to it directly.

01

Run KubePilot against your cluster

Install the Helm chart into the cluster, or run the binary with your kubeconfig.

git clone https://github.com/bwalia/kubepilot
helm upgrade --install kubepilot \
  kubepilot/charts/kubepilot \
  -n kubepilot --create-namespace
02

Make it reachable — securely

Use a port-forward to try it, or an Ingress with TLS and auth for your team. Keep it off the public internet without auth.

kubectl -n kubepilot port-forward \
  svc/kubepilot 8080:8080
03

Point the app at your server

In the KubePilot app, choose Add server (not Try demo), enter your KubePilot URL and credentials, and tap Connect. Add more clusters any time.

Try the mock API

Use it from the app or from a terminal

In the iOS app, tap Try demo on the Welcome screen and the URL and login below are filled in for you. You can also call the API directly — it's the same /api/v1 surface a real KubePilot server exposes.

Quick start

Shared demo login (read-only, synthetic data): apple / review

curl -u apple:review \
  https://demo.kubepilot.org/api/v1/troubleshooting/summary
curl -u apple:review \
  "https://demo.kubepilot.org/api/v1/clusters/pods?namespace=payments"
